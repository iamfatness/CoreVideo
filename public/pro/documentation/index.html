CoreVideo Pro Architecture

How CoreVideo Pro 1.0.0 is put together on Windows. The as-built detail, with the evidence behind each capability, lives in the project README. For the OBS plugin's internals, see the Core Plugin guide.

Three processes

  • The operator console is a native WinUI 3 app on .NET 9. It owns no real-time media: it sends production commands and draws the program, preview and multiviewer from shared GPU textures.
  • The media core is a C++ process that owns real-time pixels and audio: the Direct3D 11 compositor, the audio mixer and dynamics, the Media Foundation recorder, and every output sender.
  • The Zoom engine is a separate process that runs the Zoom Meeting SDK and writes each participant's raw video and audio to shared memory, so a problem inside the SDK cannot take the console down with it.

The console and the core talk over typed JSON-line commands and snapshots on the child process's standard input and output. Video crosses process boundaries as keyed-mutex DXGI shared textures, never as copies through a pipe.

Sources

Zoom participants arrive as separate raw 1080p video and audio sources. Webcams and capture cards are read by Media Foundation inside the core, screens and windows through Windows Graphics Capture, and local clips and stills play from a media bin with cue, live and pause owned by the core. Each source keeps its own clock and texture, and scenes select from them.

Program

A scene is a layout of slots. The operator builds the next shot in Preview and Takes it to Program. The compositor renders Program, Preview and the multiviewer on the GPU at 1080p60, with per-source framing, borders, colour grading, CoreVideo Tiles, lower thirds and graphics. A short Program buffer (two or three frames) gives every output a steady 60 fps cadence.

Outputs

The same Program feeds every output at once: an MP4 Program recording and per-guest ISO recordings on hardware encoders with isolated write queues, an SRT stream with GPU-direct HEVC or H.264 encoding or an RTMP stream, NDI with an optional graphics key, and the “CoreVideo Pro Camera” registered with the Windows Frame Server for Zoom, Teams or OBS. If the media core restarts, recording resumes and the stream reconnects on their own.

Comms

Talkback rides the Zoom Meeting SDK's private talkback channels, so the operator speaks to chosen people in the meeting without the room hearing. Private comms keeps the operator's own meeting audio silent.

How a release is qualified

Before a release, the installed build runs a 30-minute outputs soak in which every output is judged frame by frame by a picture identity stamped into Program, alongside a clean-machine install test. The 1.0.0 results are in the release notes.
